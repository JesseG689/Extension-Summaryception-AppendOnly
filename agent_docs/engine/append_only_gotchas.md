# Append-Only Gotchas

- The provider cache depends on exact message-list prefixes.
- Extend a cached prefix only when the first added message is an assistant message.
- Place baked lore after the previous assistant reply and before the current user message.
- Do not bake without a preceding assistant reply.
- Keep the previous assistant reply, baked lore, and current user message visible.
- Active dynamic lore is routed to the dedicated bake outlet on loaded entry copies.
- Never modify or save source lorebooks for automatic routing.
- Constant lore stays in its normal prompt position.
- Legacy SC - <original> selections resolve to the current original when available.
- Apply host lore processing before storing an entry.
- Store each baked entry as a complete lore block.
- Track entries by lorebook, entry identity, and source revision.
- Compare only the newest baked revision so reverting an edit can bake again.
- A visible marker prevents duplicate baking.
- A hidden marker allows baking after old history leaves the prompt.
- Resolve macros once before sending or storing baked lore.
- Exclude baked narrator messages from summarizer accounting.
- Select entries by priority. Never truncate entries or their tags.
- Enforce entry count, bake budget, and remaining provider capacity.
- Skip baking when final payload measurement is unavailable.
- Keep summary memory stable between append-only flushes.
- Update summary memory only after a flush completes.
- Inject the no-memory system block only when the user enables it.
- Keep time and date macros stable in append-only mode.
- Rewrite reasoning only in final request history.
- Do not mutate reasoning stored in chat.
- Keep surviving replacement text stable for the active chat.
- Leave a trailing assistant prefill unchanged.
- Cleanup restores migrated lore and removes baked narrator messages through the host.
- Existing history cannot be baked retroactively.
- Do not preserve baked lore through a summary flush.
- Commit cleanup with summary persistence, injection update, and hiding.
- Append-only mode does not support depth-positioned lore or group chats.
- Bake only for normal generation.
- Retry, continue, quick-reply, and dry-run paths do not bake content.
- A retry payload is rebuilt from stored chat and already contains the baked narrator block.
- The host lore scan remains the source of activation data.
